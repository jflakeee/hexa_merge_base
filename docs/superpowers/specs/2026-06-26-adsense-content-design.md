# AdSense "가치 낮은 콘텐츠" 대응 — 콘텐츠 보강 설계

- 날짜: 2026-06-26
- 목적: Google AdSense 사이트 승인 "주의 필요 / 가치가 낮은 콘텐츠(Low value content)" 해소
- 라이브: https://www.fungood.co.kr/ (게시자 `ca-pub-9645429447397687`)

## 문제

게임 본체는 `<canvas>` + JS 동적 렌더링이라 크롤러가 읽을 **정적 텍스트가 사실상 0**.
게임 방법(`HowToPlayScreen.js`)도 JS 오버레이라 크롤러 미인식. 정적 페이지는
`privacy.html` 하나뿐 → 구글이 "콘텐츠 가치 부족"으로 판단.

## 해법: 사람이 읽을 정적 HTML 콘텐츠 추가 후 재심사

### 1. 새 정적 페이지 4개 (저장소 루트)

모두 `privacy.html`과 동일 톤: `lang="ko"`, 다크 배경 `#0f0f15`, 핑크 강조 `#FF7DA3`,
폰트 `'Nunito','Apple SD Gothic Neo','Malgun Gothic',system-ui`, `.wrap{max-width:760px}`.

| 파일 | 내용 |
|------|------|
| `how-to-play.html` | 게임 목표, 조작법, 머지 등급 시스템(2개→×2, 4개→×4, 8개→×8), 타일 색/숫자, 게임오버 조건 |
| `tips.html` | 고득점 전략, 추천 플레이 패턴, 큰 묶음 유도법, 보드 관리, 흔한 실수 회피 (글량 충실) |
| `about.html` | 게임 소개, 특징, 무료/웹/오프라인, 플랫폼(모바일·데스크탑), 제작 배경 |
| `faq.html` | 저장(localStorage)·오프라인·조작·사운드·광고·요금 등 Q&A |

각 글은 실제 읽을 가치가 있게 충실히 작성(얇은 자동생성 톤 금지). 게임 메카닉은
구현 시 게임 코어 코드로 사실 검증 후 서술.

### 2. index.html 랜딩에 정적 "게임 소개" 섹션 + 내비

- 게임 시작 전 랜딩 영역(`<body>` 내 정적 DOM)에 짧은 소개 문단 + 4개 페이지 + 개인정보처리방침 링크.
- 게임 플레이 UX(HUD/canvas/광고배너)는 변경하지 않음. 소개·내비는 시작 전 랜딩에만.
- 크롤러가 `<body>` 정적 텍스트를 읽고 내부 링크로 4개 페이지를 발견하도록.

### 3. 페이지 상호 연결

- 각 새 페이지 하단에 공통 내비: 나머지 3개 페이지 + 개인정보처리방침 + "← 게임으로 돌아가기"(`./`).
- 내부 링크 구조로 "구조 있는 사이트" 신호 형성.

### 4. SEO 메타 보강

- 각 페이지와 index에 고유 `<title>`, `<meta name="description">` 부여.

### 5. 배포

- 새 html 4개를 gh-pages 복사 대상에 추가([[deploy_flow]] 절차 갱신), 배포.
- 배포 후 라이브 4개 URL HTTP 200 검증.
- 사용자가 AdSense 대시보드에서 **재검토(재심사) 요청**.

## 비목표 (YAGNI)

- 게임 플레이 로직/디자인 변경 없음.
- 다국어(영어) 페이지 없음 — 한국어 단일.
- 블로그/CMS/동적 콘텐츠 없음 — 정적 HTML만.

## 리스크

- 재심사 통과는 구글 시간(수일~2주) 소요, 100% 보장 불가. 콘텐츠 보강이 가장 효과적인 정공법.
- 글 품질이 낮으면 재거절 가능 → 충실한 분량/독자성 확보가 관건.

## 완료 기준

1. 4개 페이지 + index 소개 섹션 작성, 상호 링크 동작.
2. gh-pages 배포, 라이브 5개 URL(4 신규 + index) 정상.
3. 배포 흐름 메모리에 새 파일 복사 대상 반영.
4. 사용자에게 재심사 요청 안내.
