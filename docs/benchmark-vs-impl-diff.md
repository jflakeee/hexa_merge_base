## 0. 요약 (Executive Summary)

벤치마크는 **GAMEGOS의 "XUP"** — 숫자 육각형(flat-top) 머지 게임. 현재 구현은 컨셉/구조는 맞으나 **색·사운드·애니메이션·화면 구성·블럭 기하**에서 다수 불일치.

| 차원 | 판정 | 비고 |
|---|---|---|
| 헥사 방향(flat-top) | ✅ 일치 | 둘 다 flat-top |
| 색 램프 방향(warm→cool) | ✅ 일치 | 순서/방향은 동일 |
| 타일 색 정확 HEX | ❌ 불일치 | 15개 값 전부 다름 |
| 블럭 라운드 | ❌ 불일치 | 벤치 ≈0.39·R, 구현 샤프(0) |
| 블럭 간격 | ❌ 불일치 | 벤치 ≈0.156·R, 구현 0(맞닿음) |
| 사운드 | ❌ 불일치 | 구현은 코드 합성, 녹음 미사용 |
| 애니메이션 타이밍/이펙트 | ❌ 불일치 | 벤치가 훨씬 길고 강함 |
| 스플래시/랜딩 화면 | ❌ 없음 | 구현에 인트로 없음 |
| 일시정지 메뉴 | ❌ 불일치 | 구성 다름 |
| 게임오버 화면 | ❌ 불일치 | 구성/버튼 다름 |
| HowToPlay | ❌ 불일치 | 시각 데모 vs 텍스트 |

> 이전(15초 슬라이스 기반) 진단의 오판 2건을 풀 영상 재분석으로 정정함: ① 헥사 방향은 pointy가 아니라 **flat-top으로 일치**, ② 색 램프는 warm-only가 아니라 **쿨톤까지 일치**.

## 2. 블럭 기하 (라운드 / 간격) — 픽셀 측정

측정 정본: `res/KakaoTalk_20260219_202633217.png` (1170×2532), 19타일 검출, 원피팅.

| 항목 | 측정값(px) | 외경 R=128 대비 비율 |
|---|---|---|
| 블럭 외경 R (중심→꼭짓점) | 128 | 1.0 (변 길이 = R) |
| apothem (중심→변 중앙) | 112 | 0.875 (R/apo=1.161 → 정육각) |
| 중심간 거리 pitch | 240.5 | 1.88·R (= √3·R + gap) |
| **블럭간 간격 gap** | **20** | **0.156·R (pitch의 8.3%)** |
| **모서리 라운드 반경** | **≈50 (47~55)** | **≈0.39·R** |

- **간격**: 구현 `Renderer.hexToPixel`는 `hexSize*√3`(세로)·`hexSize*1.5`(가로)로 **맞닿는 배치(gap=0)**. 벤치는 외경의 15.6% 간격 존재 → 위치를 벌리거나 타일을 pitch의 ~86%로 그려야 함.
- **라운드**: 구현 `HexCellView.drawHexagon`은 **샤프 꼭짓점**(라운드 0). 벤치는 R의 약 39% 라운드(각 변 끝에서 ≈29px씩 깎임, 변 중앙 ~70px만 직선) → 경로를 라운드 처리(`arcTo`/quadratic, 반경 ≈ 0.39·hexSize) 필요.
- 적용 시 해상도 무관 비율 사용: **gap = 0.156·hexSize, 라운드 = 0.39·hexSize** (라운드 ±5px 오차).

## 3. 사운드

- 벤치마크 효과음 = 원본 mp4에서 추출된 **실제 녹음**(측정: `benchmark_audio.wav` 784.252s ≈ mp4 784.260s, 0~5s 구간 상관계수 1.0).
- 구현 `src/audio/ProceduralSFX.js`는 **녹음 미사용, Web Audio로 전부 코드 합성**(crystal-glass 톤). 파일 첫 줄 "No external audio files required".
- 길이도 불일치: 합성 tap=0.07s/merge=0.20s vs 벤치 실측 tap≈0.06s/merge≈0.06s, 특수음 3.0s, 엔드게임 29.25s(미구현).
- 이벤트 매핑(`main.js`): tap/buttonClick/merge(값별)/gameOver/tileDrop/crownChange/gameStart — 전부 추정 합성.

## 4. 애니메이션 / 이펙트

풀 영상 활동 프로파일(2fps) + 병합 1건 30fps 정밀 분석.

- 벤치 병합은 **연쇄(cascade)로 약 0.8~2.0초(~36프레임)** 지속.
- 시퀀스: **붉은 액체 스플랫 → 입자 폭발(마젠타 점 분산) → 보드 전체 마젠타 연쇄 플래시**(프레임 diff 28M, 거의 전 화면 변화).
- 구현: 병합 0.25s + 8px 원형 스플랫 + 6입자 → **훨씬 짧고 약함**.
- 구현 타이밍 참고(`TileAnimator.js`/`MergeEffect.js`): spawn 0.35s(elastic), merge 0.25s, scale punch 0.15s, splat 0.44s(3단계), particle 0.5s, gameover shake 0.5s.
- ※ 단일 병합만의 정확 프레임 수는 연쇄 때문에 분리 곤란. 더 정밀한 비교는 고립된 단일 병합 구간 추가 분석 필요.

## 6. 쟁점 규명 (2026-05-31 해소)

- **배포본 vs 로컬 정합 — 해소됨.** 조사 결과: `res/button`(2/23) 스크린샷은 XUP 브랜딩이었으나, 이후 구현이 "HEXA MERGE" 핑크 테마로 **드리프트**함(gh-pages 5/14 배포본 = HEXA MERGE/BEST 확인). 즉 충돌이 아니라 시간에 따른 이탈이었고, 이번 작업이 다시 XUP로 **복원**함. 로컬 `index.html`/`src`가 정본. **gh-pages는 재배포 필요**(현재 구버전 HEXA MERGE 상태).
- **게임 메카닉 — 개수 기반(How To Play 규칙, 최종).** `result = base × 2^floor(log2(N))`, N=총 병합 타일 수. 2개→×2, 4개→×4, 8개→×8 ("at least N → ×N", 거듭제곱 임계, 모양 무관). HowToPlay 화면 표기와 일치. 5케이스 단위검증 통과. (앞서 시도한 트리 기반 "부모당 ×2/자식2↑ ×4"은 사용자 요청으로 이 개수 기반으로 환원)

## 부록: 측정 방법

- 색: ffmpeg로 풀 영상 프레임 추출(12s 간격 survey + 고득점 프레임) → PIL로 채도 픽셀 색 census, blob 검출로 값별 타일 색 매핑.
- 기하: 1170px 스크린샷에서 blob 검출 → 중심/외경/apothem, 중심간 거리(pitch), 변간 gap = pitch − 2·apothem, 모서리 원피팅(±8~12° 창, 6모서리×다중 타일 중앙값).
- 사운드: ffprobe 길이/샘플레이트, mp4 0~5s 구간과 추출 wav PCM 상관계수.
- 애니: 2fps 저해상도 전체 활동 프로파일 → 활동 구간에서 30fps 추출 → 프레임간 보드 diff 엔벨로프 + 몽타주.
