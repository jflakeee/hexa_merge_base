# 디자인과 플레이어 경험

## 1. MDA: 규칙에서 경험까지 추적하기

MDA는 Mechanics(규칙·데이터), Dynamics(플레이 중 생기는 행동과 상호작용), Aesthetics(플레이어가 경험하는 정서)를 연결하는 분석 틀이다. 여기서 aesthetics는 그래픽 품질만을 뜻하지 않는다. 이 틀은 원하는 경험에서 출발해 규칙을 검토하는 데 유용하지만 재미를 자동으로 계산하는 공식은 아니다. [Hunicke·LeBlanc·Zubek 원문](https://www.cs.northwestern.edu/~hunicke/MDA.pdf).

**프로젝트 적용 예:** “보스를 준비해서 이겼다는 성취감”을 목표로 한다면, 장비 조합 규칙만 추가하는 것으로 끝나지 않는다. 플레이어가 보스의 위험을 이해하고, 대응 장비를 선택하고, 전투 결과에서 선택의 효과를 확인해야 한다. 화려한 처치 연출은 마지막 성취를 강조하지만 앞의 판단 과정을 대신하지 못한다.

| 설계 질문 | 필요한 산출물 | 확인 방법 |
|---|---|---|
| 어떤 경험인가? | 성취·발견·휴식처럼 구체적인 목표 문장 | 플레이 후 무엇이 좋았는지 자유 설명 |
| 어떤 행동에서 생기는가? | 비교·준비·실험·회피 등 관찰 가능한 행동 | 화면 녹화와 행동 기록 |
| 어떤 규칙이 그 행동을 만드는가? | 비용·제약·대안·결과 | 상태/수치 검증과 시뮬레이션 |
| 결과를 알아차리는가? | 피드백·비교 UI·결과 설명 | 이유를 설명할 수 있는지 관찰 |

## 2. 동기: 자율성·유능감·관계성

자기결정성이론을 게임에 적용한 연구는 자율성, 유능감, 관계성의 충족과 게임 경험의 관계를 설명한다. 버튼이나 콘텐츠의 수만 늘리는 것이 자율성을 보장하지는 않는다. [Przybylski·Rigby·Ryan, 2010](https://selfdeterminationtheory.org/SDT/documents/2010_PrzybylskiRigbyRyan_ROGP.pdf).

실무 질문으로 바꾸면 다음과 같다. 아래 질문은 연구를 토대로 작성한 적용 제안이다.

- **자율성:** 내가 중요하게 생각하는 목표나 방법을 선택할 수 있는가? 자동 장착을 쓰면서도 장비 고정·수동 선택을 유지할 수 있는가?
- **유능감:** 성공·실패 이유를 이해하고 다음 시도를 개선할 수 있는가? 수치가 커진 것과 규칙을 더 잘 이해한 것을 구분하는가?
- **관계성:** 다른 사람과의 의미 있는 연결이 필요한 게임인가? 싱글플레이에 소셜 기능을 의무적으로 붙이지 않고 작품의 목표에 맞게 판단한다.

SDT를 몇 가지 체크박스로 축소하는 관행에 대한 비판도 있다. Tyack·Mekler의 연구는 259편의 HCI 게임 연구 등을 살펴 피상적인 이론 사용을 문제 삼는다. 이번 조사에서는 공개 초록을 확인했다. 따라서 “세 욕구만 채우면 유지율이 오른다”는 인과적 보장으로 쓰지 않는다. [2024 연구 초록](https://arxiv.org/abs/2405.12639).

## 3. 학습 루프와 튜토리얼

Daniel Cook의 skill atom은 행동, 시스템 반응, 피드백, 이해를 연결하고, 배운 기술이 다음 기술의 기반이 되는 구조를 설명한다. 실무 설계 모델이며 모든 플레이어의 학습을 증명한 보편 법칙으로 취급하지 않는다. [저자 원문](https://www.gamedeveloper.com/design/the-chemistry-of-game-design).

현재 게임에 대한 학습 순서 제안:

```text
아이템 획득 인지 → 현재 장비와 비교 → 직접 장착 → 결과 변화 확인
                                            ↓
                      감정 → 옵션 이해 → 룬/세트 조합 실험
```

처음부터 모든 메뉴를 설명하는 대신 다음 행동에 필요한 정보가 무엇인지 관찰한다. 각 단계는 “버튼을 눌렀다”보다 “왜 눌렀는지 설명한다”로 학습 여부를 확인한다. 자동 장착은 반복 부담을 줄일 수 있으나 첫 비교 경험까지 모두 대신하면 장비 규칙을 배우기 어려울 수 있다. 이는 검증할 가설이지 자동화가 항상 나쁘다는 뜻은 아니다.

## 4. 의미 있는 선택과 깊이

여기서는 의미 있는 선택을 **알아볼 수 있는 대안, 결과 차이, 상황에 따른 장단점**이 있는 결정으로 정의한다. 이 정의는 프로젝트의 작업 기준이다.

| 문제 | 관찰 신호 | 설계 실험 |
|---|---|---|
| 지배 전략 | 어느 상황에서도 같은 장비/스킬이 최선 | 적 역할·비용·위험 조건을 바꿔 선택 이유 비교 |
| 가짜 선택 | 이름과 색만 다르고 결과가 같음 | 기능 차이를 만들거나 선택지를 정리 |
| 이해 불가능한 선택 | 결과를 예측 못하고 아무거나 고름 | 비교 정보·짧은 실험·되돌리기 제공 |
| 압도적인 선택 | 메뉴를 오래 보지만 결정을 못함 | 관련 항목 우선 노출, 기본 추천의 이유 표시 |

깊이와 복잡성은 다르다. 규칙이 적어도 조합과 상황이 다양하면 깊이가 생길 수 있다. 반대로 옵션이 많아도 항상 능력치 합계 최대만 고르면 실제 판단 폭은 좁을 수 있다. 자동 전투에서는 순간 조작 대신 전투 전 준비와 장기 자원 배분이 선택의 중심이 될 수 있다.

## 5. 난도와 몰입을 단일 숫자로 만들지 않기

도전과 능력의 관계는 유용한 질문이지만 “성공률 70%가 모든 게임의 최적점” 같은 보편 목표는 두지 않는다. 조작 난도, 정보 해석, 전략 복잡성, 벌칙, 반복 시간은 별개의 축이다. 플레이어가 실패한 이유가 학습 부족인지, 수치 부족인지, 입력 장벽인지 먼저 나눈다.

게임 난도 옵션은 여러 장벽을 조절하는 방식으로 설계할 수 있다. [Xbox Accessibility Guideline 108](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/108). 프로젝트에서는 적 체력만 조정하기 전에 예고 시간, 입력 부담, 실패 후 재시작 시간의 영향을 각각 검토한다.

GameFlow 관련 원문도 탐색했으나 이번 도구에서 PDF를 열지 못했다. 따라서 GameFlow의 세부 평가표를 검증된 근거처럼 재현하지 않았으며, 접근 제한은 [출처 문서](sources.md)에 남겼다.

## 6. 페이싱: 계속 강하게 만들기보다 강약의 의미를 설계하기

Left 4 Dead의 AI Director 발표는 긴장 형성·유지·완화·휴식의 흐름을 설명한다. 발표에서 이 조절은 난도 강도를 바꾸는 것과 구분되는 페이싱 조정이다. 해당 게임의 시간값을 다른 장르에 그대로 이식할 근거는 없다. [Valve 원문 슬라이드](https://cdn.akamai.steamstatic.com/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf).

현재 3분 전투의 실험안은 일반 적으로 규칙을 확인하고, 조합 적으로 압력을 높이고, 정리 시간을 준 뒤 마지막 위협을 제시하는 것이다. 이것을 확정 웨이브 설계로 취급하지 않는다. 각 구간의 피해량·처치량·위험 인식과 반복 체감부터 비교한다. 긴장이 낮다고 적 수만 늘리면 시각 혼잡이나 성능 저하만 커질 수 있다.

## 7. 게임 필·연출·정보의 우선순위

앞선 [애니메이션 조사](../animation-effects-beyond-30/README.md)와 [영화 연출 조사](../cinematic-animation-toon/README.md)를 디자인 목표에 연결한다.

| 상황 | 플레이어가 알아야 하는 것 | 표현 후보 | 지나칠 때 생기는 문제 |
|---|---|---|---|
| 피격 | 맞았는가, 위험한가, 대응할 수 있는가 | 실루엣 변화·HP 변화·짧은 소리 | 흔들림과 숫자가 공격 예고를 가림 |
| 성장 | 무엇이 좋아졌는가 | 전후 수치·능력 해금·짧은 강조 | 팝업이 반복 행동을 계속 끊음 |
| 실패 | 왜 실패했고 무엇을 바꿀 수 있는가 | 원인 요약·준비 화면 연결 | 연출만 길고 개선 정보 없음 |
| 보상 | 무엇을 받았고 어디에서 쓰는가 | 획득→보관 위치 연결 | 반짝임만 보이고 사용처를 모름 |

이 표는 프로젝트 설계 제안이다. 연출 성공의 기준은 “효과가 재생됐다”와 “플레이어가 필요한 정보를 이해했다”를 모두 포함한다.
