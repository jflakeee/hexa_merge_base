# 제작·플레이테스트·품질 검증

## 1. 개발 단계마다 다른 질문에 답한다

빠른 프로토타입의 목적은 큰 비용을 들이기 전에 아이디어의 핵심 불확실성을 확인하는 것이다. Experimental Gameplay Project의 제작자들은 짧은 주기의 시도와 실패에서 얻은 경험을 정리했다. 모든 게임을 일주일에 완성할 수 있다는 증거나 상용 제작 일정 공식은 아니다. [제작자 원문 재수록 PDF](https://miami.lgrace.com/documents/How%20to%20Prototype%20a%20Game%20in%20Under%207%20Days.pdf).

아래 단계 구분은 프로젝트 운영 제안이다.

| 단계 | 해결할 질문 | 필요한 결과 |
|---|---|---|
| 콘셉트 | 누구에게 어떤 경험을 주는가? | 목표 경험·대상·핵심 제약 한 페이지 |
| 프로토타입 | 핵심 행동이 이해되고 선택할 이유가 있는가? | 최소 규칙과 관찰 결과 |
| 대표 구간 제작 | 아트·소리·UI·규칙을 함께 완성할 수 있는가? | 작은 완성 구간과 제작 비용 추정 |
| 본 제작 | 같은 품질로 콘텐츠를 반복 생산할 수 있는가? | 데이터·에셋·검증 과정 |
| 안정화 | 저장·성능·진행·접근성 문제는 없는가? | 대상 환경의 검증 증거 |
| 운영·개선 | 실제 경험에서 어떤 가설이 틀렸는가? | 재현 사례·측정·수정 판단 |

프로토타입 통과 기준은 코드 줄 수나 기능 수가 아니다. 예를 들어 “장비 두 개의 차이를 플레이어가 이해하고 자신의 선택을 설명한다”가 핵심이라면 완성된 배경 아트보다 비교 화면과 전투 결과가 우선이다.

## 2. 범위와 리스크를 관리한다

기능 목록에 예상 효과, 비용, 의존성, 가장 큰 불확실성, 검증 방법을 함께 기록한다. 비용은 구현뿐 아니라 아트 변형, UI 설명, 저장 호환, 밸런스, 모바일 성능, 회귀 테스트까지 포함한다.

추천 판단 순서:

1. 현재 핵심 경험을 막는 문제인가?
2. 작은 실험으로 해결 가능성을 확인할 수 있는가?
3. 성공 시 실제 플레이 가치가 분명한가?
4. 유지 비용을 감당할 수 있는가?

영화식 카메라나 새 제작 시스템도 이 질문을 통과해야 한다. 이미 만들었다는 이유만으로 유지할 필요는 없지만, 삭제 판단 역시 사용 관찰과 유지 비용을 근거로 한다.

## 3. 플레이테스트: 행동과 해석을 함께 본다

Valve의 공개 발표는 플레이테스트를 경험적 검증 과정으로 다룬다. 이번 조사에서는 공개 슬라이드를 확인했다. 특정 스튜디오의 방법이 모든 팀의 정답이라는 뜻은 아니다. [Valve의 플레이테스트 접근](https://cdn.akamai.steamstatic.com/apps/valve/2009/GDC2009_ValvesApproachToPlaytesting.pdf).

현재 프로젝트의 관찰 세션 제안:

- 처음 보는 플레이어에게 시작 후 자유롭게 진행하도록 한다. 개발자가 먼저 조작과 최적 전략을 설명하지 않는다.
- 막힌 위치, 되돌아간 화면, 선택에 걸린 시간, 반복 실수와 발언을 기록한다.
- “재미있나요?”만 묻지 않고 “지금 목표는 무엇인가요?”, “왜 이 장비를 골랐나요?”, “다음에는 무엇을 바꾸겠나요?”처럼 이해를 확인한다.
- 문제를 발견한 즉시 사용자를 도와주면 자연스러운 행동이 바뀐다. 진행 불가능한 경우 지원한 시점을 기록한다.
- 생각을 말하게 하는 방식이 빠른 전투 수행을 바꿀 수 있으므로 관찰 세션과 성능 측정 세션의 목적을 구별한다.

소수의 질적 테스트는 문제 발견에 유용하지만 전체 이용자의 성공률이나 유지율을 추정할 충분한 표본이라는 뜻은 아니다. 정량 표본 수는 목표 오차·기대 차이·변동성·설계 조건에 따라 달라진다. [NN/g 정량 표본 안내](https://www.nngroup.com/articles/summary-quant-sample-sizes/). “5명에게 괜찮았으니 85%의 문제를 해결했다” 같은 확정 판단은 하지 않는다.

## 4. 측정은 가설과 함께 설계한다

| 질문 | 이벤트/자료 제안 | 해석상의 한계 |
|---|---|---|
| 첫 장착을 이해하는가? | 첫 획득→감정→장착 시간, 선택 이유 | 빠른 자동 장착이 이해를 뜻하지 않음 |
| 제작이 의미 있는가? | 제작 전후 빌드·자원·전투 결과 | 제작한 사람은 원래 숙련자일 수 있음 |
| 보스가 공정한가? | 실패 원인 설명, 반복 횟수, 준비 변경 | 승률만으로 공정성 측정 불가 |
| 보상이 지나치게 드문가? | 목표 첫 획득 시간 분포, 미획득 비율 | 획득자만 분석하면 오래 못 얻은 사람이 빠짐 |
| 연출이 도움이 되는가? | 정보 이해, 입력 복원, 스킵, 프레임 시간 | 재생 완료율만으로 만족 판단 불가 |

이는 계측 설계안이며 실제 수집이나 외부 서비스 연결을 수행한 것이 아니다. 이벤트에는 필요한 게임 맥락만 포함하고 데이터가 어떤 질문에 쓰이는지 명확히 한다. 이벤트 중복, 누락, 버전 혼합을 확인하지 않은 숫자는 신뢰하기 어렵다.

## 5. A/B 실험과 인과 해석

통제 실험은 먼저 반증 가능한 가설과 주요 지표, 악화를 감시할 지표, 데이터 품질 기준을 정의한다. [Microsoft Research 사전 실험 지침](https://www.microsoft.com/en-us/research/articles/patterns-of-trustworthy-experimentation-pre-experiment-stage/).

프로젝트 예시: “장비 변경의 전후 비교를 표시하면 첫 장비 선택 이유를 설명하는 비율이 높아진다.” 주 지표는 이해 여부로 두고 작업 시간·오장착·성능을 함께 본다. 유지율 상승을 곧바로 가설로 삼으면 원인 해석이 더 어려울 수 있다.

사용자 단위 배정과 그룹 유지, 필요한 표본과 기간, 중단 규칙, 효과 크기와 불확실성을 미리 정한다. 중간 결과를 반복 확인하다 유의한 순간에 임의로 끝내지 않는다. 작은 표본에서는 불확실성이 커서 차이를 검출하지 못할 수 있고, “유의하지 않다”는 “동일하다”와 다르다. 신규/기존 사용자 구성이 달라진 전후 비교를 무작위 A/B와 동일하게 부르지 않는다.

지금 규모에 충분한 실험 트래픽이 있는지는 확인하지 않았다. 초기에는 관찰·규칙 검증·시뮬레이션으로 큰 문제를 줄이고, 정량 실험에 필요한 조건이 갖춰졌을 때 확대한다.

## 6. 접근성은 경험을 유지하는 다른 경로다

Microsoft XAG는 디자인·개발·테스트에서 사용할 가이드다. 모든 지침을 그대로 적용했다는 인증과는 구별한다. [XAG 공식 목록](https://learn.microsoft.com/en-us/xbox/accessibility/guidelines).

현재 게임의 검토안은 색에 더해 형태·텍스트로 위험을 알리고, 모션 감소 상태에서도 상태 변화를 이해할 수 있게 하며, 반복 입력과 작은 클릭 대상의 부담을 점검하는 것이다. 정보 접근 장벽과 전략적 도전은 구별한다. 연출을 끄면 피격 여부까지 사라지는 구조는 목표 경험을 보존하지 못한다.

## 7. 서로 다른 검증을 결합한다

| 검증 | 잡을 수 있는 것 | 단독으로 증명 못 하는 것 |
|---|---|---|
| 단위/규칙 테스트 | 비용·보상·전이·중복 정산 | 재미·이해·시각 품질 |
| 통합 테스트 | 저장/로드·씬 이동·연결 동작 | 실제 사용자 판단 |
| 시뮬레이션 | 분포·성장 곡선·극단 입력 | 모델에 없는 행동·감정 |
| 정지 이미지 | 배치·겹침·텍스트 잘림 | 타이밍·끊김·입력 지연 |
| 영상 검토 | 시간적 일관성·전환·깜박임 | 장기 성장의 가치 |
| 플레이 관찰 | 학습·혼란·선택 이유 | 모집단의 정밀한 수치 |
| 운영 측정 | 실제 조건에서의 행동 패턴 | 무통제 상관관계의 인과성 |

출시/배포 판단에서는 검증한 버전·주소·환경을 남긴다. 로컬 빌드 성공을 운영 동작 성공으로 대신하지 않는다. 저장 호환·핵심 진행·오류·프레임 시간·작은 화면의 가독성은 배포 결과와 함께 확인한다.

연출 한 종류의 완료 기준 예: 정상 재생, 즉시 스킵, 연속 호출, 장면 종료, resize, 모션 감소에서 상태가 같고 표현이 깨지지 않는다. 이 기준은 이전 [시네마틱 적용 설계](../cinematic-animation-toon/game-application.md)와 연결된다.
