# 현재 게임에 적용할 연구 순서

아래는 2026-10-05 코드 일부를 읽고 만든 연구안이다. **확인한 코드 사실, 추론한 위험, 아직 검증하지 않은 개선 효과**를 구분한다. 버그 수정이나 기능 구현을 이번 조사에서 수행하지 않았다.

## 1. 확인한 구조

| 영역 | 코드에서 확인한 사실 | 아직 모르는 것 |
|---|---|---|
| 자동 장착 | 같은 슬롯의 statBonus 합계를 비교 | 실제 플레이에서 더 약한 빌드가 되는 빈도 |
| 전투 능력 | 세트·고유·룬워드·스킬 효과 포함 | 상황별 각 효과의 실효 가치 |
| 성장 | 다음 레벨 비용 `50×현재 레벨` | 실제 사용자별 목표 도달 시간 |
| 기본 드롭 | unique 가중치 0.5 / 총합 100 | 모든 보상 경로를 합친 실질 획득 분포 |
| 생존 전투 | 기본 종료 시간 180,000ms | 전체 구간의 체감 긴장·지루함 |
| 정산 | settled를 통한 중복 지급 방지 | 모든 취소/종료 경로의 통합 실행 결과 |
| 저장 | localStorage JSON, 기본값 병합·일부 검증 | 저장 실패 안내와 다양한 이전 저장의 복구율 |

## 2. 우선 실행할 다섯 연구

### P1. 자동 장착이 플레이어의 빌드를 보존하는가

가설: 단순 합계 비교는 세트 임계점이나 룬워드 가치를 놓칠 수 있다.

실험: 세트 완성 직전/직후, 생존형/공격형, 고유 효과 유무의 대표 상태를 만들고 후보 장비 교체 전후를 같은 적 조건에서 비교한다. 스탯 계산 비교 후 실제 전투로 확대한다.

결정: 목표별 추천, 잠금, 설명 표시 중 문제를 최소 변경으로 해결하는 방식을 선택한다. 단순 점수를 더 복잡한 임의 점수로 바꾸는 것으로 끝내지 않는다.

완료 증거: 추천의 목적, 대표 반례, 변경 전후 결과, 수동 선택 보존 여부가 문서화되어야 한다. 현재는 가설만 수립한 상태다.

### P2. 보상 목표의 기다림 분포가 의도와 맞는가

가설: 평균 획득량만 보면 일부 플레이어의 긴 미획득 구간을 놓친다.

실험: 기본 드롭·확정 보상·제작·상점 경로를 분리한 뒤 합친다. 첫 유용한 장비, 첫 세트 효과, 첫 고유 장비까지의 분포와 끝까지 미도달한 비율을 본다.

결정: 확률 변경, 확정 교환 경로, 목표 안내 중 어느 방식이 필요할지 판단한다. 유료 재화나 천장 시스템 도입은 이번 연구의 기본 전제가 아니다.

완료 증거: 모델 가정, 정책별 결과, 장기 미획득 구간, 실제 규칙과 모델의 일치 표본. 이번에 수행한 것은 기본 확률의 해석적 계산뿐이다.

### P3. 첫 성장에서 무엇을 배웠는가

가설: 획득·감정·자동 장착·제작을 빠르게 제공해도 그 관계를 모를 수 있다.

실험: 처음 보는 플레이어의 첫 진행을 관찰하고, 장비 선택 이유와 다음 목표를 설명하게 한다. UI 클릭 순서를 외웠는지보다 규칙을 이해했는지 본다.

결정: 단계적 정보 제공, 비교 UI, 첫 수동 선택 또는 자동화 설명을 검토한다.

완료 증거: 참가자 배경, 막힌 단계, 수정 전후 관찰, 아직 남은 이해 문제. 개발자의 자기 플레이만으로 통과시키지 않는다.

### P4. 전투 3분에 강약이 있는가

가설: 난도가 일정하게 증가하는 것과 긴장이 잘 구성되는 것은 다르다.

실험: 시간 구간별 위협·피해·처치·휴식·관심 이동을 기록하고 플레이 영상의 맥락과 함께 본다. 시각 효과를 끈 조건도 비교해 규칙과 표현의 영향을 나눈다.

결정: 적 구성, 구간 배치, 정리 시간, 예고 정보의 변경을 검토한다. 적 수와 화면 흔들림을 동시에 늘리지 않는다.

완료 증거: 시간대별 패턴과 플레이어 설명, 성능·가독성 악화 여부. 일정 승률 하나로 완료를 선언하지 않는다.

### P5. 규칙 결과와 연출 수명이 분리되어 있는가

가설: 새 화면 전환·카메라·보상 효과를 늘릴수록 중복 실행과 종료 복원 문제가 중요해진다.

실험: 정산 직전/직후 스킵, 창 닫기, 씬 종료, 재진입, 모션 감소, 큰 delta를 대표 시나리오로 확인한다.

결정: 상태 확정과 표현의 경계를 먼저 보강한 뒤 새 연출을 확장한다.

완료 증거: 같은 게임 결과, 중복 보상 없음, 입력/카메라/시간 복원, 오류 없는 영상. 기존 테스트 통과 기록은 새 시나리오의 실행 증거로 대신하지 않는다.

## 4. 구현 순서에 대한 제안

먼저 데이터와 관찰로 P1/P2의 위험 크기를 확인한다. 이어 P3의 학습 문제를 해결하고, 그 상태를 기준으로 P4의 전투 흐름을 다듬는다. P5의 상태·연출 경계 검증은 새로운 연출을 넣는 작업마다 병행한다. 마지막으로 기존 애니메이션·시네마틱 후보 중 경험 개선 목적이 명확한 항목을 선택한다.

이 순서는 연구 결과를 실행으로 옮길 때의 추천이며 일정 약속이나 구현 승인 요청이 아니다. 새 기능을 더 넣어야만 개선되는 것은 아니며 설명·기본값·노출 순서를 바꾸는 작은 수정이 더 효과적일 수 있다.
