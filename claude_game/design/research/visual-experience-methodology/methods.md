# 시각 경험 개선 방법론 16개

각 항목의 실험은 프로젝트 적용 제안이다. 외부 자료의 사례, 지각 연구, 접근성 권고를 동일한 수준의 인과적 증명으로 취급하지 않는다. 특정 시간값·색상·파티클 수가 모든 게임에 최적이라는 가정도 하지 않는다.

## M01. 화면의 목적과 정보 우선순위 정의

먼저 장면마다 플레이어가 답해야 하는 질문을 적는다. 전투에서는 위치·위험·행동 결과, 장비 창에서는 비교·비용·선택 결과가 중심이다. 크기·대비·배치의 위계는 이 우선순위를 반영해야 한다. 시각 계층과 균형 등은 [NN/g 시각 디자인 원칙](https://www.nngroup.com/articles/principles-visual-design/)을 참고한다.

**방법:** 한 장면의 정보를 즉시 판단, 잠시 후 확인, 선택적 장식으로 구분한다. 한순간에 모든 요소를 같은 강도로 강조하지 않는다. 짧은 화면 노출 후 무엇을 기억하는지, 플레이 중 필요한 정보를 어디서 찾는지 비교한다. 기억 결과는 실제 시선 위치 측정과 다르다.

## M02. 실루엣으로 역할 식별

TF2 제작 논문은 캐릭터 역할을 내부 음영 없이 실루엣만으로 구별할 수 있도록 설계한 과정을 설명한다. [Valve 원문](https://cdn.steamstatic.com/apps/valve/2007/NPAR07_IllustrativeRenderingInTeamFortress2.pdf).

**방법:** 색·텍스처·장식이 없어도 몸 비율·외곽·무기·자세로 구별되는지 본다. 현재 게임에는 적 역할별 형태, 공격 준비 자세, 작은 화면에서의 외곽 구분을 적용할 수 있다. 실루엣 테스트를 통과해도 배경과 겹치거나 모션이 빠르면 다시 어려워질 수 있어 실제 장면 검증을 이어간다.

## M03. 캐릭터와 배경의 분리

VALORANT 제작 자료는 미술, 성능, 게임 정보의 일관성을 함께 다루며 캐릭터 경계의 조명 강조 사례를 제시한다. [Riot 기술 원문](https://www.riotgames.com/en/news/valorant-shaders-and-gameplay-clarity).

**방법:** 캐릭터를 무조건 더 밝게 하기 전에 배경의 대비·세부 밀도·색 변화를 줄인 버전과 비교한다. 2D 픽셀 게임에서는 얇은 외곽선, 발밑 접지 그림자, 캐릭터 뒤의 단순한 바닥 영역을 검토한다. 3D Fresnel 셰이더를 2D에 그대로 이식했다고 표현하지 않는다. 모든 캐릭터를 빛나게 하면 다른 중요한 정보와 다시 경쟁할 수 있다.

## M04. 시각적 혼잡을 감산으로 해결

Rosenholtz 등의 연구는 혼잡과 시각 탐색의 관계를 다루고 특징 혼잡도·엔트로피·에지 밀도 같은 측정법을 비교한다. 이번에는 저자 초록을 확인했으며 게임 영상에 해당 모델을 구현·검증하지 않았다. [연구 초록](https://pubmed.ncbi.nlm.nih.gov/18217832/).

**방법:** 바닥 무늬, 배경 불빛, 숫자, 궤적을 각각 끈 조건을 만들어 탐색 방해 요소를 분리한다. 화면 전체 평균 에지 수만으로 복잡성을 판정하지 말고 플레이어 주변과 위험 구역을 따로 본다. 적이 많은 것은 의도된 도전일 수 있지만 장식 때문에 적을 놓치는 것은 다른 문제다.

## M05. 색·형태·위치의 시각 문법

색 하나에 의미를 맡기지 않고 형태·아이콘·문구·패턴을 함께 설계한다. 여러 전달 경로에 대한 공식 지침은 [XAG 103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103)을 참조한다.

**방법:** 위험, 회복, 보상, 선택, 비활성 상태마다 시각 토큰 표를 만든다. 같은 보라색 원이 어떤 때는 위험이고 다른 때는 안전한 버프라면 추가 단서로 구분한다. 색각 시뮬레이션은 설계 검토 도구이며 실제 해당 사용자의 경험을 대신하지 않는다. 회색조 검사도 색각 조건 전체를 대표하지 않는다.

## M06. 예고·발동·잔류를 규칙과 일치시키기

Riot의 VFX 교육 자료는 효과가 실제 행동·상태와 출처를 정확히 전달하면서 전체 스타일과 조화되어야 한다고 설명한다. [Riot VFX](https://www.riotgames.com/en/artedu/visual-effects).

**방법:** 공격마다 예고 시작, 판정 시작/종료, 잔류 효과 종료를 같은 시간축에 기록한다. 예고 경계와 실제 판정 영역을 비교한다. 장식 불꽃은 경계 밖에 있어도 되지만 판정 범위를 오해시키는 핵심 형태는 분리한다. 긴 예고라도 배경에 묻히면 도움이 안 되므로 노출 시간과 인식 여부를 함께 본다.

## M07. 동시에 발생하는 효과의 우선순위

프로젝트 제안: 위험 예고, 플레이어 상태 변화, 유효 타격, 보상, 환경 장식에 각각 우선순위를 부여한다. 파티클 개수 제한만으로는 큰 반투명 이미지 하나가 화면을 덮는 문제를 잡지 못한다.

**방법:** 동시 수 외에 화면 점유 영역·불투명도·밝기·지속 시간·가림 위치를 기록한다. 중요 이벤트가 발생하면 장식을 약화하거나 묶어 표시한다. 모든 값을 곱해 만든 임의 점수를 과학적으로 검증된 “주의 예산”이라고 부르지 않는다. 우선순위는 일관된 규칙으로 구현하고 실제 전투에서 예외를 찾는다.

## M08. 피드백의 원인과 결과 연결

프로젝트 제안: 입력→상태 변경→시각 반응→지속 표시의 연결을 추적한다. 피격 섬광이 강해도 현재 체력을 오해하면 좋은 피드백이 아니다.

**방법:** 즉시 바뀌는 현재 값과 잠시 남는 이력 표시를 구분한다. 체력 지연 바는 방금 잃은 양을 보여주되 현재 HP로 오해되지 않게 한다. 보상은 순간 숫자뿐 아니라 보관 위치·누적 값으로 확인할 수 있어야 한다. 강도·시간을 한 번에 바꾸지 않고 이해율과 만족 반응을 따로 비교한다.

## M09. 카메라를 정보 전달 장치로 평가

자동 시점 변경·흔들림·블러에 대한 선택권은 [XAG 117](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117)에서 다룬다.

**방법:** 카메라 확대가 보여주는 정보와 가리는 정보를 함께 기록한다. 보스 소개에는 얼굴 확대가 적절할 수 있지만 공격 회피 중에는 주변 위험을 숨길 수 있다. 카메라 움직임 종료 후 원래 중심·줌·입력이 복원되는지 검증한다. 2D 스크롤과 영화 팬, 스케일 확대와 실제 돌리의 차이는 [기존 촬영 연구](../cinematic-animation-toon/cinematography.md)를 따른다.

## M10. 모션 감소를 동등한 정보 경로로 설계

**방법:** 흔들림을 끈 조건에서도 피격, 확대를 끈 조건에서도 보스 등장, 보상 비행을 끈 조건에서도 획득 위치를 이해할 수 있게 한다. 정적인 강조·아이콘·텍스트를 대안으로 검토한다. 모션 감소, 점멸 감소, UI 배경 애니메이션 정지는 별도 문제일 수 있다. 하나의 설정을 적용했다고 모든 시각 접근성 요구를 충족했다고 판단하지 않는다. 관련 권고는 [XAG 117](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117).

## M11. HUD와 메뉴를 과업 단위로 묶기

**방법:** 관련 정보와 행동을 가까이 배치하고 반복되는 위치를 유지한다. 장비명·효과·비용·장착 버튼이 서로 다른 곳에 흩어지지 않게 한다. 전투 중 HUD와 제작 중 패널은 우선순위가 다르므로 동일한 정보 밀도를 강요하지 않는다. 작은 화면에서는 중요 정보부터 유지하고 보조 정보는 펼쳐 볼 수 있게 한다. 적게 보이는 것과 쉽게 이해되는 것을 동일시하지 않는다. 배치 원칙 참고: [NN/g](https://www.nngroup.com/articles/principles-visual-design/).

## M12. 텍스트를 실제 표시 조건으로 검사

글자 크기·서체·배경·확대 설정을 함께 검토한다. [XAG 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101).

**방법:** 한국어 긴 문구, 숫자 자리수 증가, 작은 화면, 확대된 글꼴에서 잘림·겹침·줄바꿈을 검사한다. 픽셀 서체의 분위기와 본문 가독성을 별도로 판단한다. CSS px, 캔버스 논리 좌표, 실제 장치 픽셀은 같지 않을 수 있다. 큰 모니터에서 축소 이미지로만 읽어보는 것은 실제 휴대전화 조건의 대체가 아니다.

## M13. 대비를 최악의 배경에서 확인

XAG 102는 일반 크기의 중요한 텍스트·시각 요소에 4.5:1, 큰 요소에 3:1 등의 권고를 제시하며 복잡한 배경에서는 가장 대비가 낮은 부분을 고려한다. [XAG 102](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102). 여기서 크기 분류와 적용 범위는 해당 지침을 따라 확인해야 하며 모든 게임 픽셀에 일률적으로 적용하는 규칙은 아니다.

**방법:** 밝은 공격 효과가 뒤를 지날 때, 반투명 패널 뒤 배경이 바뀔 때도 검사한다. 평균 배경색만으로 대비를 계산하지 않는다. UI 불투명 배경이나 테두리를 먼저 비교하고, 대비 수치 통과와 게임 상황 식별 성공을 별도 검증한다.

## M14. 픽셀·선·패턴의 시간적 안정성

`image-rendering: pixelated`는 확대 샘플링에 도움을 주지만 모든 배율·기기에서 균일한 픽셀 모양을 보장하지 않는다. [MDN 픽셀 아트 자료](https://developer.mozilla.org/en-US/docs/Games/Techniques/Crisp_pixel_art_look).

**방법:** 이동·줌·resize 중 픽셀 폭, 외곽선, 바닥 패턴의 떨림을 본다. CSS 확대와 캔버스 렌더링 해상도·텍스처 필터링을 분리해 확인한다. 픽셀 좌표 반올림은 선명도를 높이면서 낮은 속도의 계단 이동을 만들 수도 있어 두 조건을 비교한다. 카툰 해칭·라인 보일은 의도된 변화와 우발적 깜박임을 구별한다.

## M15. 아트 디렉션을 재사용 규칙으로 문서화

**방법:** 팔레트 역할, 명암 단계, 외곽선 두께, 픽셀 밀도, 광원 방향, VFX 형태, 움직임 성격, UI 여백을 한 장의 스타일 기준으로 만든다. 각 규칙에는 정상 예와 피해야 할 예를 붙인다. TF2의 사례는 형태·음영·세계 구성의 협업을 참고할 수 있으나 그 미술 양식을 복제할 필요는 없다. [Valve 원문](https://cdn.steamstatic.com/apps/valve/2007/NPAR07_IllustrativeRenderingInTeamFortress2.pdf).

같은 스타일 안에서도 중요한 대상의 대비와 역할 차이는 보존한다. 모든 자산을 같은 색·같은 움직임으로 만드는 것이 일관성은 아니다. 분위기·재질·캐릭터성은 식별성과 함께 평가하며 정량 지표 하나로 합치지 않는다.

## M16. 성능 설정에서도 핵심 정보를 보존

Riot의 VALORANT 사례는 품질 설정 차이가 중요한 정보를 바꾸지 않도록 하는 설계를 설명한다. [기술 원문](https://www.riotgames.com/en/news/valorant-shaders-and-gameplay-clarity).

**방법:** 낮은 품질에서는 장식 입자·잔향·배경 세부를 줄여도 위험 경계와 필수 상태는 유지한다. 같은 설정의 평균 FPS보다 느린 프레임, 입력 반응, 패턴 안정성을 함께 검사한다. 성능을 위해 예고 효과 자체를 없애거나, 고품질에서만 적 위치를 알려주는 그림자를 추가하지 않도록 한다. 현재 게임의 설정 정책은 별도 실행 검증이 필요하다.
