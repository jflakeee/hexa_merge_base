# 시각 경험 개선 검증 프로토콜

이 문서는 실행할 검증 계획이다. 이번 연구에서 새 플레이 영상, 참가자 데이터, 색 대비 측정값을 만들지는 않았다. 다음 절차와 지표는 프로젝트용 제안이며 표준화된 시각 품질 점수 체계가 아니다.

## 1. 개선 목표를 분리한다

| 차원 | 확인할 질문 | 적합한 자료 |
|---|---|---|
| 탐색 | 필요한 대상이 어디인지 찾는가? | 찾기 과업, 오선택, 탐색 시간 |
| 해석 | 색·형태·바가 무엇을 뜻하는지 아는가? | 상태 설명, 위험/안전 분류 |
| 행동 | 정보를 보고 적절히 대응할 수 있는가? | 플레이 영상, 대응 시점, 실패 맥락 |
| 감각적 만족 | 타격·보상·이동이 원하는 느낌을 주는가? | 쌍대 비교와 이유 설명 |
| 스타일 | 분위기와 자산이 조화되는가? | 스타일 기준과 아트 리뷰 |
| 편안함 | 움직임과 정보 밀도가 부담스럽지 않은가? | 선호 설정, 중단·불편 보고 |
| 안정성 | 저사양·작은 화면에서도 일관적인가? | 프레임 시간, resize, 픽셀·레이아웃 검토 |

높은 만족 점수가 위험 인식 실패를 상쇄했다고 판단하지 않는다. 객관적 오류와 취향을 구분하고, 한 숫자로 종합하기 전에 각 차원의 결과를 남긴다.

## 2. 기준 장면을 고정한다

최소 장면 묶음 제안은 방치 이동, 일반 전투, 효과가 겹치는 전투, 보스 예고, 보상/결과, 장비/설정이다. 각 장면의 게임 버전, 초기 상태, 난수 시드 또는 입력 재생, 뷰포트, 장치 배율, 브라우저, 품질·모션 설정을 기록한다.

기준 장면에는 보기 좋은 대표 프레임뿐 아니라 위험과 보상이 동시에 생기는 경우, 긴 텍스트, 최저 체력, 인벤토리 포화, 밝은 효과 뒤의 UI처럼 읽기 어려운 조건을 포함한다. 테스트 장면의 최대 밀도는 실제 게임이 허용하는 범위인지 표시한다.

## 3. 변경 요인을 나눠 비교한다

예시 가설: “바닥 선의 대비를 낮추면 캐릭터 찾기 시간이 줄고 적 역할 식별 정확도는 유지된다.”

| 조건 | 바뀌는 것 | 고정할 것 |
|---|---|---|
| A 기준 | 없음 | 적·캐릭터 위치, UI, 효과, 시간 |
| B 배경 정리 | 바닥 선/작은 장식 대비 | 캐릭터 색·크기·윤곽 |
| C 캐릭터 강조 | 캐릭터 윤곽만 변경 | 배경과 다른 요소 |
| D 조합 | B+C | 나머지 조건 |

한 번에 배경·캐릭터·카메라·폰트를 모두 바꾸면 좋아졌더라도 이유를 분리하기 어렵다. 학습·순서 영향을 줄이기 위해 A/B 순서를 바꾸고 장면을 반복 암기하지 않게 한다. 작은 관찰 실험은 문제 발견에 활용하고 모집단의 효과 크기를 확정하지 않는다. 정량 표본 설계는 [기존 게임 이론의 검증 연구](../game-development-theory/validation-production.md)를 참고한다.

## 4. 정지 이미지 검사

원본 크기, 실제 표시 크기, 축소 보기에서 계층과 식별성을 확인한다. 실루엣, 회색조, 대비 강조 보기 등은 진단 도구다. 원본에서 필요한 정보를 잃는 변환도 있으므로 변환 이미지 하나로 통과/실패를 단정하지 않는다.

측정 제안:

- 텍스트가 가장 불리한 배경 위에서 읽히는지, 확대 시 잘리지 않는지.
- 위험 경계가 HUD·캐릭터·장식에 가려지는 위치가 있는지.
- 중요한 요소와 장식이 같은 색·크기·밝기로 경쟁하는지.
- 캐릭터 종류와 효과 출처를 설명할 수 있는지.

정지 이미지의 그림자·파티클 위치만으로 실제 판정 범위를 추정하지 않는다. 대비는 XAG 102의 적용 범위와 실제 렌더 결과를 함께 확인한다. [공식 지침](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102).

## 5. 영상과 이벤트 시간축 검사

```text
규칙:  예고 시작 ─── 판정 시작 ─── 판정 종료
표현:  표시 시작 ─── 강조/폭발 ─── 잔류 종료
입력:  입력 가능 ── 제한 여부 ─── 복원
```

세 시간축을 나란히 본다. 실제 시간·시뮬레이션 시간·슬로모션 배율을 구별하고 캡처 FPS로 환산할 때 그 값을 기록한다. 녹화 프레임 누락과 게임 자체의 끊김도 구별한다.

| 지표 | 작업 정의 | 한계 |
|---|---|---|
| 예고 노출 시간 | 시각 예고 시작부터 실제 판정 시작까지 | 길다고 인지되는 것은 아님 |
| 예고 가림 비율 | 예고 구간 중 사전 정의한 핵심 경계가 가려진 프레임 비율 | 핵심 경계·가림 판정 규칙을 먼저 정해야 함 |
| 상태 인식 오류 | 현재 HP·위험 상태를 잘못 답한 횟수/유효 질문 수 | 질문 자체가 주의를 유도할 수 있음 |
| 화면 탐색 시간 | 과업 제시부터 올바른 대상 선택까지 | 첫 시선 도달 시간과 다름 |
| 경계 일치 | 개발용 판정 오버레이와 표현 경계를 비교 | 원근·높이·장식 영역을 명시해야 함 |
| 프레임 시간 | 같은 조건의 중앙값·상위 지연·최대값 | 브라우저 예약 간격만으로 GPU 비용을 단정 못 함 |

예고 가림 비율은 이 프로젝트의 진단 지표이며 특정 허용 비율을 보편 표준으로 주장하지 않는다. 가림 면적이 작아도 핵심 방향 단서가 사라지면 치명적일 수 있다.

## 6. 사용자 확인 과업

처음 보는 사용자와 익숙한 사용자를 구분한다. 다음과 같은 질문을 실제 장면과 함께 사용한다.

1. 지금 조작하는 캐릭터와 가장 위험한 대상을 가리킨다.
2. 원형 효과를 보고 들어가도 되는지, 누구의 효과인지 설명한다.
3. 피격 후 현재 체력과 방금 잃은 체력을 구분한다.
4. 보상을 받은 뒤 무엇을 얻었고 어디에 있는지 찾는다.
5. A/B 연출 중 선호를 말하고 이유를 설명한다.

진행자가 정답을 설명한 이후의 결과는 학습 전 이해와 섞지 않는다. 시선 추적 장비를 쓰지 않았다면 클릭·응답으로 시선 데이터를 수집했다고 표현하지 않는다. 시선 추적을 하더라도 응시가 이해를 보장하지 않는다.

## 7. 설정·기기 검증 행렬

| 축 | 제안 조건 | 우선 확인 |
|---|---|---|
| 화면 | 좁은 세로, 데스크톱, 낮은 높이 | HUD 가림, 주요 버튼, 글자 잘림 |
| 배율 | 일반/고 DPI, 브라우저 확대 | 픽셀 불균일, 폰트, 좌표 연결 |
| 모션 | 기본, 게임 설정 끔, OS 감소 설정 | 동일 정보 유지, 섬광 별도 검토 |
| 품질 | 기본, 장식 감소 | 위험 예고와 상태 정보 보존 |
| 성능 | 대표 저사양, 효과 최대 겹침 | 느린 프레임, 입력 반응, 누적 메모리 |
| 수명주기 | resize, 탭 복귀, 장면 종료, 연속 호출 | 잔류 효과, 카메라/입력 복원 |

실제 기기 목록과 목표 프레임률은 구현 실험 전에 정한다. 이 표는 모바일 호환성 또는 접근성을 이미 인증했다는 뜻이 아니다.

## 8. 채택 기준

구현 전에 주 지표와 악화되면 안 되는 조건을 정한다. 예를 들어 배경 정리안은 대상 식별이 개선되고 분위기 선호·위험 경계 가독성·성능이 허용 범위에 있을 때 채택한다. 작은 표본에서 수치 차이가 나왔다면 관찰 결과와 불확실성을 함께 기록한다.

차이를 찾지 못하면 “동일한 품질”로 단정하지 않는다. 문제가 없는 영역은 유지하고 큰 영향을 주는 변경부터 반복한다. 새 효과 수나 파일 수를 시각 경험 개선의 증거로 사용하지 않는다.
