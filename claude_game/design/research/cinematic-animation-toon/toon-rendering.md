# 카툰·NPR 렌더링과 애니메이션: 12개 연구 항목

NPR은 사진 같은 재현 이외의 시각 표현을 다룬다. 카툰 외에도 연필·잉크·회화 표현이 포함된다. 아래는 기법 조사와 프로젝트 적용 제안이며 셰이더를 실행해 검증한 결과가 아니다.

## 1. 기법과 구현 경로

| N08 | 페인터리/브러시 스트로크 | 붓 자국으로 형태·색을 표현 | 배경 에셋을 먼저 회화 스타일로 제작. 화면에 고정된 종이 질감과 물체 표면 질감을 구분. |
| N09 | 라인 보일/텍스처 보일 | 선·질감의 작은 변화로 손그림 생동감 | 의도적으로 만든 2~3개 변형을 제한 주기로 교체. 무작위 픽셀 노이즈와 구별. |

### 명암과 윤곽선의 근거

Blender의 `Shader to RGB`는 EEVEE에서 셰이딩 결과를 색으로 다루어 Color Ramp 같은 변환과 연결할 수 있다. 엔진별 제약을 확인해야 하며 Cycles의 Toon BSDF와 같은 것으로 취급하면 안 된다. [Blender 4.1 공식 문서](https://docs.blender.org/manual/en/4.1/render/shader_nodes/converter/shader_to_rgb.html). Freestyle은 선 기반 NPR 방식이며 실시간 게임의 후처리와 동일한 비용 모델이 아니다. [Blender Freestyle 문서](https://docs.blender.org/manual/en/2.90/render/freestyle/introduction.html).

Unity Toon Shader는 윤곽 확장 방식과 폭 제어 등을 제공한다. 오목한 부분이나 메시 연결부에서 선이 어떻게 보이는지 자산별 검증이 필요하다. [Unity Toon Shader Outline](https://docs.unity3d.com/Packages/com.unity.toonshader@0.11/manual/Outline.html). 음영·림·외곽선의 스타일 파라미터 사례는 [VRM MToon 공식 문서](https://vrm.dev/en/univrm/shaders/shader_mtoon/)를 참조한다. 이 기능들을 Phaser에 기본 내장된 기능으로 가정하지 않는다.

### 선과 질감의 시간적 안정성

Disney의 Paperman 논문은 3D 움직임 정보를 활용해 작가가 그린 2D 선을 움직이는 표면과 연결하는 제작 방식을 설명한다. 선을 만드는 사람의 판단과 보정이 포함된다. [Disney 원문](https://media.disneyanimation.com/uploads/production/publication_asset/122/asset/pman.pdf).

Real-Time Hatching은 톤과 해상도 변화에 대응하는 해칭 맵 체계를 연구한다. 단일 선 텍스처를 모든 크기에 그대로 적용하는 것보다 명암·축소에 따른 패턴 변화도 설계해야 한다는 참고가 된다. [원문 논문](https://icg.gwu.edu/sites/g/files/zaxdzs6126/files/downloads/Real-Time%20Hatching.pdf).

Meier의 Painterly Rendering 연구는 3D와 연결된 붓 자국으로 프레임 간 일관성을 다룬다. 게임 적용 제안은 물체에 붙은 패턴과 화면에 붙은 종이 질감을 의도적으로 구분하는 것이다. [Disney 보관 원문](https://media.disneyanimation.com/uploads/production/publication_asset/47/asset/p477-meier_1996.pdf).

Sony Pictures Imageworks는 Spider-Verse에서 온 투스와 시뮬레이션·복잡한 카메라 움직임을 함께 다루었다고 설명한다. 24fps에서 그림을 두 프레임씩 유지하면 초당 12개 고유 이미지가 된다. 이것은 전체 게임을 12fps로 실행하라는 뜻이 아니다. [공식 제작 설명](https://dev.imageworks.com/our-craft/feature-animation/movies/spider-man-spider-verse). 이 조사에서는 해당 자료의 검색에 노출된 제작 설명을 확인했으며 페이지 직접 열기는 오류가 발생했다. 작품의 모든 렌더링 기법을 직접 검증했다고 주장하지 않는다.

## 2. 실제 제작 경로 비교

| 경로 | 준비물 | 장점 | 한계/추천 용도 |
|---|---|---|---|
| 수작업 2D 픽셀 | 팔레트·외곽선 규칙·핵심 포즈·스미어 | 현재 미술 스타일 유지, 렌더 비용 예측 쉬움 | 방향별 그림 필요. 현재 프로젝트 우선 추천. |
| 3D 제작 후 2D로 렌더 | 모델·리그·카메라·툰 셰이더·스프라이트 출력 | 회전·조명 변형 자산 제작 편리 | 런타임 시점은 출력한 방향에 제한. 프레임/텍스처 용량 관리. |
| 실시간 3D NPR | 메시·노멀·깊이·조명·툰 파이프라인 | 실제 오빗·돌리·형태 기반 음영 | 현재 2D 구조에서 큰 변경. 연구용 별도 프로토타입이 적절. |
| 2D 화면 후처리 | 렌더 텍스처·마스크·셰이더 | 색상/해칭/제한된 윤곽 실험 빠름 | 가려진 면·실제 깊이는 복원 못함. UI 분리와 WebGL 지원 확인. |

## 3. 개발 실험 제안

1. 동일한 보스 포즈로 원본, 3단계 팔레트, 윤곽선, 스크린톤의 네 시안을 만든다. 한 번에 하나의 변수만 바꾼다.
2. 정지 이미지 다음에 이동·확대·피격·표정 변경을 포함한 10초 반복 영상을 비교한다. 예쁜 정지 화면만으로 품질을 통과시키지 않는다.
3. 선 두께와 명암 영역을 화면 픽셀 기준으로 확인한다. 해상도 변경 때 선이 끊기거나 지나치게 굵어지지 않게 한다.
4. 의도한 라인 보일은 유지하되 그림자 경계·해칭의 우발적인 깜박임은 제거한다. 셰이더 경계에는 필요에 따라 완만한 전이 또는 시간 안정화 적용을 검토한다.
5. 같은 장면에서 공격 예고와 피해 숫자를 읽을 수 있는지 확인한다. 결과가 불리하면 장식 효과 강도부터 낮춘다.

현재 게임의 추천 조합은 **제한 팔레트 + 수작업 명암 + 얇은 윤곽선 + 중요한 동작의 스미어 + 캐릭터별 포즈 유지 시간**이다. 전면 실시간 3D NPR 도입보다 작은 자산 실험으로 먼저 검증하자는 프로젝트 판단이다.
