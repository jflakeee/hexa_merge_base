# 촬영·편집·카메라: 36개 연구 항목

아래 표의 적용 예는 ClaudeGame을 위한 설계 제안이다. 시간·강도는 실측 최적값이 아니다. 편집은 장면 사이의 관계, 카메라는 시점과 시선 유도, 촬영은 공간·빛·시간을 조직하는 방법으로 구분한다.

## 1. 화면 전환과 편집 — E01~E12

| ID | 기법 | 목적/원리 | 게임 적용 제안과 주의점 |
|---|---|---|---|
| E01 | 하드 컷 | 중간 혼합 없이 다음 숏으로 전환 | 전투→결과를 즉시 연결. 결과 상태가 먼저 준비되어 빈 프레임이 없어야 한다. |
| E02 | 매치 온 액션 | 진행 중인 행동을 다음 숏에서도 이어 연속감 형성 | 검을 휘두르는 방향과 동작 위상을 컷 전후 일치. 같은 프레임 단순 반복과 구분. |
| E03 | 그래픽 매치 | 형태·위치·색의 유사성으로 장면 연결 | 원형 보석→원형 보스 문양. 연결할 두 화면을 함께 설계해야 효과적. |
| E04 | 시선 매치 | 바라보는 인물 다음에 시선 대상을 제시 | 보스 눈→플레이어/목표. 좌우 관계가 뒤집히지 않도록 한다. |
| E05 | J 컷 | 다음 장면 소리가 화면보다 먼저 시작 | 보스 울음이 먼저 들리고 보스 등장. 소리만 듣고 이미 공격 시작으로 오해하지 않게 한다. |
| E06 | L 컷 | 이전 장면 소리가 다음 화면까지 이어짐 | 처치 잔향을 결과 창까지 유지. 장면 종료가 음원을 즉시 끊지 않도록 별도 수명 관리. |
| E07 | 디졸브 | 두 영상을 잠시 겹쳐 시간·상태 변화 연결 | 지역 분위기 교체. HUD 글자까지 겹치면 읽기 어려우므로 월드 레이어 중심. |
| E08 | 페이드 | 화면을 단색으로 사라지게 하거나 드러냄 | 로딩·지역 이동. 암전 완료와 실제 전환 완료를 이벤트로 동기화. 기존 30종과 중복. |
| E09 | 와이프/아이리스 | 움직이는 경계나 원형 마스크로 교체 | 포털 진입. 경계 형태의 변형이며 각각을 독립 신규 효과로 세지 않는다. |
| E10 | 가림 전환/히든 컷 | 물체·어둠이 화면을 가릴 때 컷을 숨김 | 전경 기둥 통과 순간 지역 교체. 가림이 충분하지 않으면 위치 점프가 보임. |
| E11 | 휩 팬 전환 | 빠른 회전/이동의 흐림과 방향으로 컷 연결 | 보스 소개에서 짧게 사용. 2D에서는 빠른 화면 이동으로 근사; 반복 전투에는 과함. |
| E12 | 교차 편집/몽타주 | 여러 행동·시간의 배열로 긴장 또는 압축 | 원정 요약, 양쪽 준비 동작. 교차 편집의 동시성 암시와 몽타주의 시간 압축은 구별. |

매치 컷의 형태·행동·소리 연결은 [Adobe 설명](https://www.adobe.com/in/creativecloud/video/discover/match-cut.html), J/L 컷의 음향 선후 관계는 [Adobe 편집 문서](https://helpx.adobe.com/ca/premiere/desktop/edit-projects/trim-clips/perform-j-cuts-and-l-cuts.html)를 참조했다. 시선·공간 관계는 아래 180도 축과 함께 검토한다. 전환 기법은 장면 관계를 전달할 때 선택하며, 모든 버튼 클릭에 영화 전환을 적용할 필요는 없다.

## 2. 카메라와 초점 — C01~C12

| ID | 기법 | 물리적 변화 | 2D 게임에서의 표현/제약 |
|---|---|---|---|
| C01 | 팬 Pan | 고정 위치에서 좌우 회전 | 넓은 배경을 가로로 보여주어 근사. Phaser pan은 월드를 바라보는 중심을 스크롤하므로 물리적 팬과 다름. |
| C02 | 틸트 Tilt | 고정 위치에서 상하 회전 | 거대 보스의 아래→위 공개. 2D 세로 스크롤은 원근 변화 없는 근사. |
| C03 | 돌리 인/아웃 | 카메라가 대상 쪽/반대쪽으로 이동 | 레이어별 확대 속도로 깊이 근사. 단일 이미지 확대는 줌 표현에 가까움. |
| C04 | 트럭/크랩 | 옆으로 평행 이동 | 배경 시차를 동반한 횡이동. 2D에서 구현하기 쉬운 편. |
| C05 | 페데스털 | 회전 없이 카메라 위치 상승/하강 | 층 사이 이동 또는 무대 공개. 틸트와 구별. |
| C06 | 크레인/붐 | 높이·공간을 크게 가로지르는 이동 | 장면 전체에서 주인공으로 접근. 단일 스프라이트로 가려진 뒷면을 새로 만들 수 없음. |
| C07 | 오빗/아크 | 대상을 중심으로 원호 이동 | 방향별 캐릭터 에셋 또는 3D 필요. 평면 스프라이트 회전만으로는 실제 오빗 불가. |
| C08 | 트래킹/팔로 | 움직이는 대상을 따라 구성 유지 | dead zone·look-ahead·damping. 이동 방식이 아니라 대상과의 관계이며 돌리 등과 결합. |
| C09 | 줌 | 초점거리/화각 변경 | Phaser camera.zoom으로 간단히 표현. 픽셀 크기와 HUD 확대 여부 확인. |
| C10 | 돌리 줌 | 카메라 이동과 반대 방향 줌으로 대상 크기 유지 | 전경 크기 고정+배경 상대 확대의 2D 근사. 실제 원근 효과라고 표시하지 않는다. |
| C11 | 랙 포커스 | 초점면을 다른 거리로 이동 | 분리된 전경/후경의 흐림 교환. 카메라 이동·줌과 별개. |
| C12 | 핸드헬드/안정화 이동 | 의도적 미세 움직임 또는 안정된 이동 | 불안/관찰 느낌 선택. 핸드헬드는 반복적인 타격 screen shake와 목적이 다름. |

팬·틸트·이동의 기본 구분은 [Columbia Pan Shot](https://filmglossary.ccnmtl.columbia.edu/term/pan-shot/), [Camera Movement](https://filmglossary.ccnmtl.columbia.edu/term/camera-movement/), [Dolly](https://filmglossary.ccnmtl.columbia.edu/term/dolly-dolly-shot/)를 참조했다. 촬영 현장마다 dolly/tracking/trucking 용어 범위가 겹칠 수 있다. 돌리 줌의 대상 크기 유지 원리는 [Adobe](https://www.adobe.com/creativecloud/video/production/cinematography/camera-shots-and-angles/dolly-zoom-shot.html), 거리 기반 초점 흐림은 [Epic DOF 문서](https://dev.epicgames.com/documentation/unreal-engine/depth-of-field-in-unreal-engine?lang=en-US)를 참조했다.

**원근을 바꾸는 것은 시점의 이동이다.** 카메라 위치를 고정한 채 초점거리만 변경하면 화각과 배율이 변한다. 같은 인물 크기를 유지하면서 긴 렌즈로 바꾸려고 뒤로 이동할 때 배경의 상대 크기도 달라진다. 게임에서 zoom만 바꾸면서 이를 실제 돌리나 렌즈 압축 재현이라고 부르지 않는다.

## 3. 구도·렌즈·빛·시간 — F01~F12

| ID | 기법 | 표현 목적 | 게임 적용 제안/판단 기준 |
|---|---|---|---|
| F01 | 숏 크기 | 와이드로 위치, 클로즈업으로 표정/세부 정보 | 보스 전체→눈→플레이 공간. 적 공격 범위가 필요한 순간에는 다시 넓게. |
| F02 | 하이/로우/더치 앵글 | 위계·규모·불안정감 표현 | 로우 앵글은 별도 그림 필요. 화면 회전만으로 낮은 시점을 만들 수 없음. 더치 앵글은 제한적으로. |
| F03 | 180도 축/스크린 방향 | 인물 간 좌우 관계 유지 | 플레이어 왼쪽·적 오른쪽을 컷에서도 유지. 축을 넘으면 공간을 재설명하는 숏 배치. |
| F04 | 리드 룸/네거티브 스페이스/유도선 | 시선과 이동 방향에 공간 부여 | 진행 방향 앞을 넓게, 보스 얼굴 주변은 UI와 장식으로 가리지 않기. 3분할은 선택 가능한 구성법. |
| F05 | 화각과 촬영 거리 | 공간감을 설계 | 광각 느낌을 원하면 전경·후경 크기 대비부터 설계. 무조건 원근 왜곡 필터를 더하지 않기. |
| F06 | 조리개/피사계 심도 | 초점 대상과 주변 분리 | 액션 판정 대상은 선명하게. HUD나 공격 예고까지 흐리지 않기. |
| F07 | 셔터/모션 블러 | 노출 중 움직임의 흔적 | 픽셀 게임은 전면 블러보다 스미어 프레임 검토. 블러로 낮은 FPS를 해결했다고 판단하지 않기. |
| F08 | 촬영/재생 속도·스피드 램프 | 슬로모션·시간 압축·속도 전환 | 연출 시간과 전투 시뮬레이션 시간 분리. 속도 복원 누락과 오디오 피치 확인. |
| F09 | 키/필/백 라이트 | 형태·명암·윤곽 분리 | 보스 키 라이트+얇은 림을 그림으로 제작. 조명 세 개를 반드시 배치해야 한다는 규칙은 아님. |
| F10 | 하이 키/로우 키 | 명암 대비와 장면 분위기 조절 | 휴식은 부드러운 대비, 위협은 선택적 어둠. 단순 과노출/저노출과 구별. |
| F11 | 프랙티컬/동기 있는 조명 | 보이는 광원과 빛의 방향에 설득력 부여 | 횃불 주변 팔레트와 그림자 방향 일치. 광원 스프라이트만으로 다른 물체가 자동 조명되지는 않음. |
| F12 | 롱 테이크/커버리지 | 끊김 없는 경험 또는 편집 선택지 확보 | 이동 장면은 연속 카메라, 대사는 와이드·표정·반응 컷 확보. 긴 숏 자체가 좋은 연출을 보장하지 않음. |

공간 연속성은 [Columbia 180도 규칙](https://filmglossary.ccnmtl.columbia.edu/term/180-degree-rule/), 촬영 요소의 개괄은 [Adobe cinematography](https://www.adobe.com/creativecloud/video/production/cinematography.html)를 참조했다. 키·필·분리 조명의 역할과 광원 크기에 따른 빛의 성질은 [ARRI Lighting Handbook](https://www.arri.com/resource/blob/83996/409091c612f371b0c68b41d9dcb636db/arri-lighting-handbook-english-data.pdf)의 조명 기초 및 역할 구분을 참고했다. 게임 적용 열은 자체 제안이다.

셔터각 모델의 노출 시간은 `t = 셔터각 / (360 × FPS)`다. 24fps에서 180도면 1/48초이며, 작은 셔터각은 움직임 흔적을 줄이고 끊겨 보이는 인상을 강화할 수 있다. [ARRI 셔터 백서](https://www.arri.com/resource/blob/186770/ad23969317dafff402f0902d47bb4ab7/alexa-studio-electronic-and-mirror-shutter-white-paper-data.pdf). **180도 셔터와 인물 배치의 180도 축은 서로 다른 개념이다.** 엔진의 프레임 시간, 애니메이션 포즈 갱신률, 물리 시간 배율도 별개다.

## 4. 기존 조사와의 관계

E08/E09는 기존 Fade/Directional Wipe의 연출 확장이다. C09는 기존 Zoom Punch와 API가 겹치지만 장시간 시선 유도에도 사용한다. C08·C11은 추가 목록 A22·A21과 겹친다. F08은 기존 Hit Slow Motion과 연결된다. 따라서 이 표를 기존 30+24에 더해 새 효과 90종이라고 계산하지 않는다.
