# 현재 구현과 분석 근거

## 1. 이미 있는 기능은 유지하고 개선한다

| 영역 | 코드에서 확인한 구현 | 연구 적용 판단 |
|---|---|---|
| 피격 | targetId/방향 사건, 65ms 상당 플래시, 120ms 시각 반동 | 새로 만들지 않고 식별·연속 피격·섬광 설정 검토 |
| 체력 | 실제 HP와 지연 이력 바, 회복/재피격 처리 | 두 바의 의미를 처음 보는 사용자도 구별하는지 확인 |
| 처치 | 판정 제거와 별도의 200ms 잔상 | 수명 구조 유지; 고급 디졸브는 낮은 우선순위 |
| 보상 | 280ms 골드 표시 보간, 420ms HUD 비행 | 위치/카메라 변환·합산·의미 연결 보완 |
| 성공 종료 | 보상 먼저 정산·저장, 420ms 결과 대기 및 스킵 | 유지; 보스 소개나 확대 추가 시 복원 경로 검증 |
| UI | hover/focus/press, 결과 모달의 이동·opacity 진입 | 실제 scale-in/overshoot 구현과 구별 |
| 설정 | 게임 motion과 OS 감소 선호, CSS 감소 처리 | 기본 연결은 있음; 섬광·영역별 정책은 추가 검토 |
| 예산 | 숫자 24개, 보상 비행 5개, 기존 QA의 음향 제한 | 개수 외 우선순위·가림 위치로 확장 |
| 전투 정보 | 보스 예고, 저주/오라 원, 텍스트 상태 | 의미별 형태와 판정 경계 검토 |

## 2. 자동 장착의 실제 교환 관계 확인

프로덕션 함수를 가져와 격리된 캐릭터에 실제 생성 규칙의 세트 무기·세트 갑옷을 장착했다. 감정된 고유 무기를 후보로 넣으면 다음 결과가 나온다.

| 항목 | 교체 전 | 교체 후 |
|---|---:|---:|
| 비교 대상 무기의 단순 능력치 합 | 15 | 18 |
| 캐릭터 공격 | 31 | 27 |
| 캐릭터 방어 | 26 | 21 |
| 치명타 확률 | 5% | 약 15% |
| 세트 부위 수 | 2 | 1 |

자동 장착은 실행됐다. 이는 **세트 보너스 손실과 치명타 이득이 동시에 발생하는 선택**이다. 모든 전투에서 더 나빠진다고 입증한 것은 아니다. 다만 단순 합계만으로 “더 좋은 장비”를 설명하기는 어렵다는 구체적 근거다.

추천은 임의의 복잡한 점수 하나를 바로 도입하는 대신 전후 능력치·잃는 세트/룬 효과를 먼저 표시하고 자동 교체의 보호 조건을 정하는 것이다. 장비 잠금·현재 빌드 유지 옵션을 검토한다. 근거: [autoEquip](../../../src/systems/autoEquip.js), [effectiveStats](../../../src/systems/effectiveStats.js), [확인 결과](probe-results.json).

## 3. 보라색 원과 보스 돌진

`CombatScene.drawEffects`의 정예 leader 원은 반경 100이며 `updateEncounters`는 살아 있는 leader와 플레이어의 거리가 100 미만일 때 playerHex를 갱신한다. 따라서 이전 시각 연구의 “원 의미 미확인”은 코드 수준에서 **정예 저주 범위**로 갱신할 수 있다. 해당 장면의 모든 픽셀을 재생해 검증한 것은 아니다.

돌진은 선 두께 10으로 표시하고 끝점에 반경 20의 원을 그린다. 판정은 플레이어 중심과 선분 사이 거리 22 미만이다. 격리 실행에서도 거리 15에서 피해가 발생했다.

여기서 선의 반폭 5와 중심 거리 22의 차이만으로 결함이라고 단정하면 안 된다. 플레이어 충돌 크기를 포함한 접촉 범위일 수 있기 때문이다. **표현 경계, 플레이어 충돌 크기, 판정 시점의 명시적 계약**을 만들고 오버레이로 비교하는 것이 먼저다. nova의 반경 60 원은 실제 지속 원형 피해가 아니라 탄막 발생 표현이며, 위험 문법에서도 blast·charge와 구분할 가치가 있다.

근거: [encounters](../../../src/systems/encounters.js), [CombatScene](../../../src/scenes/CombatScene.js), [확인 스크립트](probes.mjs).

## 4. UI 재배치 애니메이션의 선행 조건

BottomPanel은 변경된 HTML일 때만 갱신하며 pointerDown/SELECT 활성 중 갱신을 피하고 스크롤·필드 값을 복원한다. 이미 있는 보호 장치를 유지해야 한다. 다만 `content.innerHTML` 교체는 노드 정체성을 보존하지 않으므로 FLIP/공유 요소 이동을 붙이기 전에 항목 ID, 포커스 복원, 빠른 연속 갱신을 정리해야 한다.

현재 버튼에는 `data-item-id`가 있지만 모든 목록 행이 안정된 노드로 유지되는 구조와는 다르다. 모든 아이템을 매번 등장시키는 stagger는 실시간 갱신 UI에서 반복 피로를 만들 수 있다. [BottomPanel](../../../src/ui/BottomPanel.js).

## 5. 카메라·모션 확장의 선행 조건

보상 비행의 현재 월드→화면 계산은 scroll과 표시 크기 비율을 사용한다. 향후 zoom/rotation/별도 viewport를 추가할 때 전체 카메라 변환에 맞는지 확인해야 한다. 현재 기본 카메라에서 위치 오류를 재현한 것은 아니다.

`flashSprite`와 CombatScene의 직접 tint 처리에는 모션 판정이 적용되지 않지만 반동·shake 등에는 적용된다. 움직임 감소와 섬광 감소를 같은 요구로 가정하지 말고 설정 설명과 정보 대안을 정해야 한다.

IdleScene은 배경 한 덩어리를 이동하며 resize 때 children을 재생성하고 tween을 정리한다. 다층 시차·소품 리그는 이 수명주기를 함께 다뤄야 한다. 또한 idle와 arena의 진행은 delta 상한을 사용한다. 이전 연구의 큰 delta 우려를 이 호출 경로에서 이미 재현된 결함으로 취급하지 않는다.

## 6. 검증 증거의 범위

[기존 표현 QA](../../qa/2026-10-05/presentation/review.md)에는 당시 118개 테스트, 고정 상태 캡처, 스킵·정산·모션 감소 확인이 있다. [기존 배포 QA](../../qa/2026-10-05/deployment/review.md)에는 당시 공개 URL·포털 iframe 확인이 있다. 이 기록은 이번 신규 실행 결과나 실제 모바일 장시간 성능 측정이 아니다.

이번 추가 실행은 두 함수 수준 확인뿐이다. 저장 파일·운영 상태를 변경하지 않고 메모리 객체만 사용했다. 자동 장착 결과의 승률 영향과 돌진 표현의 실제 가독성은 여전히 미검증이다.
