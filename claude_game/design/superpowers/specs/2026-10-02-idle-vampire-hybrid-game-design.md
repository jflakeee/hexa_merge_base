# 2D 픽셀 방치형 × 뱀서류 하이브리드 모바일 게임 — 설계

## 배경

- 초기 아이디어(`idea_claude_game.md`)는 세 가지 레퍼런스에서 출발했다.
  - Claude 마스코트 픽셀 캐릭터가 등장하는 내러티브형 미니게임 "Clawd's Quest" (claude.dev 쇼케이스 영상) — 비주얼/캐릭터 톤 레퍼런스.
  - "바르디안(Vardian)" — 2D 픽셀 도트, 세로화면, 방치형 액션 RPG(미궁 탐사) — 장르/UI 레이아웃 레퍼런스.
  - 기존 `D:\htdocs\diablo_clone` 프로젝트 — 디아블로2 클론. 아이템 드롭률/등급, 룬워드, 큐빙, 감정, 스킬트리, 몬스터 AI, 보스 패턴 등이 이미 구현되어 있고 Godot + Web export로 GitHub Pages 배포 중.
- 목표는 이 세 레퍼런스를 결합한 신규 브라우저 모바일 게임: **클로드 마스코트풍 2D 픽셀 캐릭터**가 주인공이고, **평소엔 방치형**으로 자동 진행되며, 플레이어가 원할 때 **뱀서류(생존형 액션) 전투**로 전환할 수 있는 구조. `diablo_clone`의 RPG 시스템 로직(수식·테이블 단위)을 최대한 참고해 깊이를 더한다.

## 목표

- 방치형 진행과 능동 조작(뱀서류 전투)을 하나의 캐릭터 성장 루프 안에서 자연스럽게 연결한다.
- `diablo_clone`에서 검증된 아이템/스킬 시스템의 핵심만 가져와 MVP 범위를 과도하게 키우지 않는다.
- 브라우저(모바일 세로화면)에서 서버 없이 동작하는 1인 플레이용 MVP로 시작한다.

## 코어 루프

1. **방치 모드 (기본 상태)**: 화면 상단 액션 영역에서 캐릭터가 횡스크롤 맵을 좌우로 자동 이동하며 몬스터를 자동 전투로 처치한다. 스테이지 끝에 도달하면 다음 스테이지로 순환 진행하며 경험치·골드·아이템이 자동으로 누적된다.
2. **전환**: 상단 액션 영역을 탭하면 화면이 **전체화면 뱀서류 전투**로 전환된다. (버튼 UI가 아니라 액션 영역 자체가 진입 지점을 겸한다.)
3. **전투 모드**: 고정 시간(3~5분, 실제 값은 밸런싱 시 조정) 동안 쏟아지는 적을 상대로 생존한다. 플레이어는 **이동만 조작**하며 공격은 장착 스킬/장비 기준으로 자동 발동된다(뱀서류 장르 표준). 타이머가 다 차면 클리어 보상을 지급하고, 체력이 0이 되면 중도 실패하되 그 시점까지 획득한 보상은 정산되어 유지된다.
4. **복귀**: 전투 중 언제든 "나가기" 버튼으로 방치 모드에 복귀할 수 있다. 두 모드는 `Character`/`Item`/`Currency` 상태를 공유하는 **동일 재화 풀**을 쓴다 — 방치 모드는 안정적인 베이스라인 수익, 뱀서류 전투는 짧고 밀도 높은 파밍 구간으로 역할이 나뉜다.

## 화면 / UI 구조

**레이아웃 (세로형, 모바일 우선)**

- **상단 60~70%**: 액션 영역. 2D 픽셀 캐릭터가 횡스크롤 맵을 자동 이동하며 전투. 탭하면 전체화면 뱀서류 모드로 전환.
- **하단 30~40%**: 관리 UI, 탭 4개.
  - **장비/인벤토리**: 보유 장비 목록, 자동 장착 최소 등급 설정.
  - **스킬/기본 스탯**: 보유 스킬(1~2개) 및 캐릭터 기본 스탯(공격력/방어력/치명 등) 확인.
  - **설정**: 사운드, 알림, 자동 진행 on/off 등 일반 옵션.
  - **상점/거래**: 골드로 아이템/장비를 구매하는 단순 교환형. 경매장 등 복잡한 거래 시스템은 MVP 범위 밖.

**전체화면 전투 UI**

- 좌측 상단: 남은 생존 시간 타이머.
- 이동 입력(가상 조이스틱 또는 드래그).
- 우측 상단: 나가기 버튼.
- 체력바: 캐릭터 머리 위 또는 화면 상단 고정.

## MVP 시스템 범위

`diablo_clone`에 이미 구현된 시스템(아이템 드롭률/분류, 룬워드, 큐빙, 감정, 스킬트리, 몬스터 AI, 보스 공격 루틴, 저주/오라, 몬스터 팩 배치, 보스룸 아레나 등) 중 **1차는 최소 핵심만** 가져온다.

- **아이템 등급/드롭률**: 일반 → 고급 → 희귀 → 영웅의 4단계로 단순화(기존 세분화 등급 체계는 2차 확장). 몬스터 처치 시 등급별 확률 테이블로 드롭 판정.
- **자동 장착**: 플레이어가 "자동 장착 최소 등급"을 설정(예: 희귀 이상만). 드롭 장비가 기준 이상이면서 기존 장착템보다 능력치 총합이 높으면 자동 교체. 기본값은 "일반 등급 이상 전부 자동 장착".
- **스킬트리(1~2개)**: 패시브 성격의 스킬만 포함 — 예: 공격력 증가 계열 1개, 생존(회복/방어) 계열 1개. 레벨업 시 포인트 투자로 강화. 방치 전투와 뱀서류 전투 모두에 동일하게 적용된다.

룬워드·큐빙·감정·저주/오라·몬스터 팩·보스 전용 패턴·보스룸 아레나·경매장 고도화는 모두 2차 이후로 미룬다(아래 로드맵 참고).

## 데이터 모델 (초안)

```
Character { level, exp, stats{atk, def, crit}, equippedItems[], skillPoints, skills{} }
Item { id, name, grade, statBonus{}, slot }
RunState { mode: 'idle' | 'combat', stageIndex, combatTimer }
Currency { gold, exp }
```

`Character`/`Item`/`Currency`는 방치 모드와 전투 모드가 공유하는 단일 상태로 관리한다(모드별 별도 자원 없음 — 재화 풀 공유 원칙과 일치).

## 기술 스택 & 아키텍처

- **엔진**: 웹 네이티브 JS, **Phaser** 권장. 스프라이트 애니메이션·타일맵 기반 횡스크롤·아케이드 물리(뱀서류 전투의 적/투사체 처리)를 기본 제공해 PixiJS(저수준 렌더링 전용)보다 두 모드 모두에 적합하다.
- **상태 관리**: 방치 루프와 전투 루프를 각각 별도 Phaser Scene으로 구현하되, `Character`/`Item`/`Currency` 상태는 Scene 외부의 전역 스토어(단순 JS 객체 + 이벤트 버스)에 두어 두 Scene이 동일 상태를 읽고 쓴다.
- **저장**: 서버 없이 `localStorage`에 진행 상태를 직렬화한다. MVP 범위에서는 계정/서버 동기화를 제외한다.
- **`diablo_clone` 연동 방식**: 엔진이 다르므로(Godot/GDScript vs. Phaser/JS) 코드를 직접 가져오지 않는다. **드롭률 테이블·등급별 배율·스킬 수식 같은 데이터/로직만 JSON·JS로 포팅**하는 것이 유일하게 현실적인 재사용 경로다.

## 에러 처리 & 엣지 케이스

- **전투 중 새로고침/이탈**: 전투 시작 시점 상태를 스냅샷으로 저장해두고, 복귀 시 전투는 실패 처리하되 그 시점까지 쌓인 재화는 정산해 반영한다(먹튀 방지와 플레이어 손해 최소화의 절충).
- **인벤토리 초과**: 꽉 찬 상태에서 자동 장착 대상이 아닌 드롭은 즉시 골드로 환산해 흡수한다(드롭 유실 방지).

1. 룬워드 / 큐빙 시스템
2. 아이템 감정 시스템
3. 저주/오라 효과, 몬스터 팩 군집 배치
4. 보스 전용 공격 패턴 및 보스룸 아레나
5. 경매장/거래 고도화
